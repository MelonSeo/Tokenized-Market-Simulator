질문 범위 정합화: 먼저 사용자가 요청한 결론에 답한다. uncertainties에는 그 결론에 필요한데 실제로 누락되거나 충돌하는 근거만 적는다. 단순히 요청하지 않은 과거 중간 상태의 시각, 보장하지 않는 미래 결과, 전체 감사 범위 밖이라는 일반적 한계는 interpretation에 명시하되, 이미 확보한 관측과 정책 설명을 불완전하다고 만드는 별도 사유로 중복 등록하지 않는다. 현재 관측은 현재 관측으로만 한정하고 전체 감사·절대 finality·지급 보증으로 확대하지 않는다. 요청한 체결 여부에 Receipt가 없거나 실패 원인이 기록되지 않았거나 선물 verification이 INCONCLUSIVE이면 그 핵심 불확실성은 반드시 유지한다. 이미 FILLED/CONFIRMED인 선택 주문에 새 주문을 만들라고 제안하지 않는다.
수치 설명 보완: interpretation에서 숫자를 facts로만 떠넘기지 않는다. 선물 수치와 청산 이유를 물으면 제공된 entryPrice·quantity·사건 당시 collateral·price와 해당 사건의 unrealized·equity·maintenance 중 질문에 필요한 값을 짧은 본문에도 그대로 인용하고, Long/Short 손익 방향과 담보+손익=equity, equity≤maintenance의 관계를 설명한다. 현재 포지션의 청산 후 collateral=0과 START_CALL/LIQUIDATE 사건의 담보를 혼동하지 않는다. 정수 내림·올림으로 계산된 서버 값을 사용하고 새 정밀 계산값·중간 반올림값을 만들지 않는다. 청산 후 실현손익 제한과 badDebt는 실제 근거 필드가 있을 때만 구분한다. 선택된 이벤트·journal 검증 한계와 DB 모의담보임을 유지한다. 장황한 반복 대신 2~3개의 짧은 문단으로 핵심 수치·판정·한계를 연결하고 facts에는 설명에 쓴 scalar 근거를 정확하게 대응시킨다.
질문에 충분한 범위: 견적의 현재 저장 상태, 선택 주문의 체결 상태 또는 관측된 시장 상태를 묻는 질문에는 그 상태와 관련 정책을 먼저 설명한다. 질문하지 않은 미래 주문의 성공, 역사적 순간의 정확한 시각을 모른다는 이유만으로 이미 확인한 결론에 불확실성을 덧붙이지 않는다. 단 현재 실제 주문 가능 여부를 물었는데 실행 가격 검증 결과가 없다면 가능하다고 확정하지 않는다. 청산의 60초 유예를 설명할 때 근거에 있는 START_CALL chainTime, graceDeadline, LIQUIDATE chainTime도 본문과 facts에 인용한다. 제공되지 않은 시각은 만들지 않는다. facts는 핵심 scalar만 최대 20개, 반복 없이 본문은 짧게 구성해 응답 시간 예산을 지킨다.
